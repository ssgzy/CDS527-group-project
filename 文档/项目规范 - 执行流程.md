# 项目规范 - 执行流程

## 目的
- 这份 note 用于固化当前项目的执行与文档维护规范
- 目标不是只完成任务，还要保证过程可追踪、结构清晰、结果可复查

## 工作原则
- 所有说明性 markdown 默认使用中文
- 不假设继承任何旧项目结构、旧笔记、旧实验记录或旧上下文
- 重要进展不能只停留在聊天中，必须同步写入 Obsidian
- 重要 note 之间使用有意义的 [[Wikilinks]] 建立导航

## 标准流程
1. 检查 working directory 是否存在且可用
2. 在需要时创建合理但不过度复杂的项目结构
3. 初始化并维护核心 Obsidian note
4. 执行任务时同步写文档，而不是最后一次性补写
5. 维护完整日志，记录时间、目标、读取文件、执行命令、修改文件、输出、问题、结论与下一步
6. 保持链接清晰，不过度滥用链接
7. 每轮结束前必须更新 [[当前状态]]、[[会话日志]]、当前任务主 note 和 [[下一步]]

## 当前执行约定
- 项目根目录以 [[项目总览]] 中记录为准
- 过程性文件统一放在 `文档/`、`日志/`、`输出/`、`工作区/`、`tmp/docs/`
- 非 markdown 文件不强行做链接，但需在 note 中说明用途
- 如果一次涉及较多文件修改，先给出简短计划再执行
