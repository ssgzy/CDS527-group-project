# 可复现性与产物同步

> 关联：[[二次核对项目 - 主文档]] | [[流程设计复核]] | [[数据版本与标签分布复核]] | [[PPT 与 Report 需补充说明]]

---

## 这一部分不是“方法错了”，而是“项目工程状态不够整齐”

- 当前项目最主要的非方法性问题，是**产物同步不足**
- 换句话说：
  - 结果大体可信
  - 但“如何从当前仓库一键重建这些结果”这件事，不够完整

---

## 已确认的不同步点

### 1. notebook 不是当前 `输出/` 的完整单一来源

- 当前 `工作区/Group_X.code.ipynb` 可以解释主实验链：
  - baseline
  - S2 model comparison
  - S3 representation comparison
  - S4 improvement & analysis
- 但 notebook 当前内容里**没有**看到：
  - `reports/*.txt` 的写出逻辑
  - `data/*.csv` 的写出逻辑

### 2. `fig3` 和 `fig4` 的生成代码不在当前 notebook 中

- 仓库里有：
  - `输出/figures/fig3_wordcount_boxplot.png`
  - `输出/figures/fig4_text_noise.png`
- 但当前 notebook 里可检索到的 `savefig()` 只明确包含：
  - `fig1`
  - `fig2`
  - `fig5`
  - `fig6`
  - `fig7`
  - `fig8`
  - `fig9`
  - `fig10`

### 3. EDA 图片保存路径前后不一致

- notebook 中：
  - `fig1 / fig2 / fig5` 保存到 `../输出/`
- 仓库最终文件：
  - 在 `输出/figures/`
- 这说明输出目录经历过二次整理，但 notebook 没有完全回写同步

### 4. notebook 当前是“干净源文件”状态

- `execution_count` 和 cell outputs 当前为空
- 这本身不一定错误
- 但如果最终交付想强调“可直接审阅运行结果”，最好决定是否保留运行输出版本

### 5. 中间生成脚本不在项目目录里

- 日志显示：
  - `Section 2 / 3 / 4` 的部分输出来自 `/tmp/step*.py`
- 这些脚本不在当前项目目录中
- 这意味着当前仓库保留了结果，但没保留完整生成过程

### 6. PPT 文件命名重复

- `CDS527.pptx`
- `Text_Classification_and_Google_Strategic_Audit.pptx`
- 两者 `sha1` 完全一致，是同一份文件的重复副本

### 7. GAI 声明口径偏旧

- `工作区/Group_X.gai.docx` 目前只写了 `ChatGPT (OpenAI GPT-4)`
- 没有覆盖后续使用的 `Claude Code / Codex` 之类工具

---

## 这些问题会带来什么风险

### 对老师审阅的风险

- 老师如果只看结果，不一定构成问题
- 老师如果想检查“仓库是否自洽、是否能复跑”，就会发现：
  - 输出与 notebook 并非完全一一对应

### 对答辩的风险

- 如果被追问“这张图是哪段代码生成的？”
- 对 `fig1`、S2、S3、S4 你可以回答
- 但对 `fig3`、`fig4`、`reports/*.txt`、`data/*.csv`，当前仓库证据链不够完整

---

## 我的判断

- 这不是结果造假迹象
- 更像是：
  - 先做出结果
  - 后来整理目录和 notebook
  - 但没有把所有工程细节统一回一个最终版本

---

## 最高优先级补救项

1. 在 report / oral 里统一“以 notebook 为主线，输出目录为导出结果”
2. 不要声称当前 notebook 单独就能重建所有 `输出/` 文件
3. 如果还有时间，最好补：
   - `fig3 / fig4` 生成代码
   - `reports/*.txt` 与 `data/*.csv` 导出代码
   - 统一所有 `savefig()` 到 `输出/figures/`
4. 统一最终提交 PPT 文件名
5. 修正 GAI 声明
